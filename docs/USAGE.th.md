# ใช้ MiroBridgeMCP ในงานจริง
[English](USAGE.md)

ทุกอย่างในหน้านี้วัดหรือสังเกตจากบอร์ดจริง (Windows 11, Miro desktop app, บอร์ดที่มี 238 item) ไม่ได้เดาเอา

## ภาพรวมการทำงานในภาพเดียว

```
your AI app ──stdio──> MiroBridgeMCP ──┐
another AI app ─stdio─> MiroBridgeMCP ─┤ (shares the first one)
                                       ▼
                    bridge on localhost:7788 (background service, starts at login)
                                       │ WebSocket
                                       ▼
          MiroBridgeMCP app inside your open board (Miro Web SDK, runs as you)
```

- แอปฝั่ง Miro เป็นหน้าเว็บที่ซ่อนอยู่ ให้บริการโดย bridge บนเครื่อง**ของคุณเอง** ข้อมูลบอร์ดวิ่งแค่ บอร์ด ⇄ เครื่องของคุณ ⇄ แอป AI ของคุณ ไม่ไปที่อื่น
- `setup` จะติดตั้ง background service ตัวเล็กๆ ที่เริ่มทำงานตอน login ดังนั้นเปิดบอร์ดเมื่อไหร่ก็เจอ bridge เสมอ แอป AI แต่ละตัวจะเปิด process MiroBridgeMCP ของตัวเอง แล้วต่อเข้ากับ bridge ที่รันอยู่แล้ว

## ห้านาทีแรก

1. `npm install -g github:sawaddee123/MiroBridgeMCP` แล้วตามด้วย `miro-bridge-mcp setup`
2. เมื่อเบราว์เซอร์เปิดขึ้นมา ให้ติดตั้งแอป Miro เข้าทีมของคุณ (ทำแค่ครั้งแรก)
3. เปิดบอร์ดไหนก็ได้ของทีมนั้น `setup` จะรอ แล้วพิมพ์ `OK board connected`
4. แอป AI อื่นๆ: รัน `miro-bridge-mcp config` แล้ววาง snippet ของแอปนั้น
5. รีสตาร์ทแอป AI แล้วลองถาม: *"บอร์ดนี้มีอะไรบ้าง"*

## บอก AI ว่าให้ดูตรงไหน: Focus

บอร์ดใหญ่มักมีไอเดียเก่า ดราฟต์ และของอ้างอิงสะสมอยู่เยอะ Focus คือการบอกว่า "ตอนนี้เราทำงานกับส่วนนี้"

| วิธี | ผลที่ได้ |
|---|---|
| เลือก item → คลิก **ไอคอนแอป** ในแถบเครื่องมือด้านซ้าย | Focus = item ที่เลือก ถ้าไม่ได้เลือกอะไรจะเป็นการล้าง focus |
| เลือก item → **Focus AI here** / **Add to AI focus** / **Remove from AI focus** ในแถบเครื่องมือของ item *(beta)* | แทนที่ / เพิ่ม / ลด focus |
| บอก AI ว่า: *"โฟกัสที่เฟรม Act 2"* | AI จะเรียก `set_focus` |

- การ focus **เฟรม** จะรวมทุกอย่างบนเฟรมนั้น รวมถึง item ที่วางทับอยู่แต่ไม่ได้ผูกกับเฟรม และ connector ระหว่าง item เหล่านั้นด้วย (วัดได้: 1 เฟรม → 48 item รวม connector 19 เส้น)
- Focus เป็น **จุดเริ่มต้น ไม่ใช่รั้วกั้น** AI จะอ่าน focus ก่อน แต่ยังอ่านส่วนอื่นได้ถ้างานต้องใช้ ("เทียบกับเวอร์ชันเก่าหน่อย")
- Focus ถูกบันทึกไว้ในบอร์ด พรุ่งนี้ก็ยังอยู่ และแอป AI ทุกตัวมองเห็นเหมือนกัน

เคล็ดลับ: ปักหมุดไอคอนแอปไว้ (แถบเครื่องมือด้านซ้าย → **More apps** → กดดาว) จะได้กดได้ในคลิกเดียว

## พฤติกรรมที่ควรรู้ (เป็นของ Miro ไม่ใช่บั๊ก)

- **ลบ shape แล้ว connector ของมันจะหายไปด้วย** `delete_items` จะรายงาน connector เหล่านั้นว่า `alreadyGone`
- **พิกัดในเฟรมเป็นพิกัดสัมพัทธ์** ตอนสร้าง item ใช้พิกัดของบอร์ด แต่ตอนอ่านกลับจะได้พิกัดเทียบกับมุมซ้ายบนของเฟรม คำอธิบาย tool บอกเรื่องนี้กับ AI ไว้แล้ว
- **Miro หยุดวาดหน้าต่างที่ถูกบังหรือถูกย่อ** การเพิ่มของเข้าเฟรมจะล้มเหลวด้วย *"isn't inside a parent frame"* และ `zoom_to` จะค้าง บน Windows bridge จะยกหน้าต่าง Miro ขึ้นมาโดยไม่แย่งโฟกัสคีย์บอร์ดแล้วลองใหม่ 1 ครั้ง OS อื่นให้เปิดไว้บนจอ ถ้า batch ล้มเหลวจะ rollback ทั้งหมด จึงไม่มีงานค้างครึ่งๆ กลางๆ
- **SDK มองไม่เห็นเนื้อหาตารางและเส้นปากกา** จะได้แค่ type `unsupported` / `curve` กับกรอบตำแหน่ง AI อ่านด้วย `capture` สร้างตาราง Miro จริงไม่ได้ (วาดด้วย `create_table` แทน) และวาดเส้นปากกาไม่ได้ (วาดเป็นภาพ SVG แทน)
- **เปิดบอร์ดหลายแท็บ:** แท็บที่เปิดล่าสุดจะเป็นตัวรับคำสั่ง ถ้าปิดแท็บนั้นจะกลับไปใช้แท็บก่อนหน้า
- **Rate limit:** Web SDK มีลิมิตต่อผู้ใช้ต่อนาที batch ใหญ่ไม่มีปัญหา แต่เรียกทีละอันเป็นพันครั้งไม่ได้

## ดูแลให้ทำงานได้ดี

| คำสั่ง | ใช้เมื่อ |
|---|---|
| `miro-bridge-mcp check` | รู้สึกว่ามีอะไรแปลกๆ จะแสดงสถานะ service, การเริ่มตอน login, บอร์ด, เวอร์ชันแอป และเมนูบนบอร์ด แต่ละข้อเป็น OK/FAIL |
| `miro-bridge-mcp setup` | หลังอัปเดต หรือเมื่อต้องการซ่อม รันซ้ำได้อย่างปลอดภัย: รีสตาร์ท service ตัวเก่า ลงทะเบียนใหม่ และข้ามหน้าติดตั้งถ้ามีบอร์ดเชื่อมต่ออยู่แล้ว |
| `miro-bridge-mcp config` | เพิ่มแอป AI ตัวอื่น |
| `miro-bridge-mcp uninstall` | ลบ service ที่เริ่มตอน login หยุดการทำงาน และยกเลิกการลงทะเบียนกับ Claude Code จากนั้นรัน `npm rm -g miro-bridge-mcp` |

**การอัปเดต:** รัน `npm install -g github:sawaddee123/MiroBridgeMCP` แล้ว `miro-bridge-mcp setup` จากนั้นรีโหลดแท็บบอร์ดที่เปิดอยู่หนึ่งครั้ง ถ้าลืมรีโหลด AI จะได้รับแจ้งว่าบอร์ดยังรันแอปเวอร์ชันเก่า และจะขอให้คุณรีโหลด

**Log:** background service เขียน log ไว้ที่ `%TEMP%\mirobridgemcp.log` (macOS/Linux: `$TMPDIR/mirobridgemcp.log`) หนึ่งบรรทัดคือหนึ่งเหตุการณ์ (บอร์ดเชื่อมต่อแล้ว, โหลดหน้าแอปแล้ว...)

## แก้ปัญหาตามอาการ

| อาการ | สาเหตุ → วิธีแก้ |
|---|---|
| "No Miro board connected" | บอร์ดถูกปิด หรือยังไม่ได้ติดตั้งแอปในทีม*ของบอร์ดนั้น* ให้เปิดบอร์ดของทีมที่ถูกต้อง แล้วรัน `check` |
| เชื่อมต่อได้ก็ต่อเมื่อกด F5 | background service ไม่ได้รันอยู่ (ปกติจะเริ่มตอน login) ให้รัน `setup` หนึ่งครั้ง |
| เมนูในแถบเครื่องมือไม่ขึ้น | ฟีเจอร์ beta (custom actions ของ Miro ยังเป็น experimental) `check` จะบอกว่าลงทะเบียนได้กี่อันและ error จาก Miro ระหว่างนี้ใช้ไอคอนแอปแทน |
| `capture` ล้มเหลว | ใช้ได้แค่บน Windows และหน้าต่าง Miro ต้องไม่ถูกย่อ (มีหน้าต่างอื่นบังได้) |
| Brave เชื่อมต่อไม่ได้เลย | Brave บล็อก localhost เป็นค่าเริ่มต้น: Settings → Privacy → อนุญาต **Localhost access** ให้ miro.com |
| Safari | ไม่รองรับ (บล็อกการเชื่อมต่อในเครื่อง) ให้ใช้ Chrome, Edge หรือ Miro desktop app |
| "port 7788 is used by another program" | มีโปรแกรมอื่นใช้พอร์ตนี้อยู่: ตั้งค่า `MIRO_BRIDGE_PORT` (และแก้ App URL ของแอป Miro ด้วย) |

## ใช้แอป Miro ของคุณเอง

ลิงก์ติดตั้งเริ่มต้นใช้แอป Miro ของผู้ดูแลโปรเจกต์ ถ้าต้องการโฮสต์เอง (โค้ดเดียวกัน แต่คุณควบคุมเอง) ดูหัวข้อ *Host your own Miro app* ใน README แล้วอัปโหลด `assets/miro-icon-outline.svg` (แถบเครื่องมือ, สีเดียว) และ `assets/miro-icon-colored.svg` ในส่วน Display information ของแอป
